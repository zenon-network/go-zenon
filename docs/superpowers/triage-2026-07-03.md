## Catalogue corrections found during verification

- **#28 / #46 — NOT-A-BUG.** Both entries misread the storage API:
  `Spork.Save` and the accelerator's `Project/Phase/PillarVote/VotableHash`
  `Save`/`Delete` are **void** methods that call `common.DealWithErr`
  *internally* (vm/embedded/definition/spork.go:56, accelerator.go:127-132,
  common.go:456-461, 520-525). No error is discarded anywhere; a DB failure
  panics in both styles. The contrast with error-returning Save methods
  (StakeInfo, TokenInfo, …) is a style asymmetry only.
- **#11 — half fixed.** PR #57 fixed `GetAllUnwrapTokenRequests`
  (SliceStable at bridge.go:592). `GetAllUnwrapTokenRequestsByToAddress`
  still uses non-stable `sort.Slice` (bridge.go:647) — and its
  `toAddress == ""` branch returns the list entirely **unsorted**.
- **#21 — overstated.** The sole `NewTask` caller (pillar/worker.go:83-88)
  starts its action with `defer common.RecoverStack()`, so `t.finish()` does
  run after a panic today. The real hazard is in the caller: a recovered
  panic in `w.work` skips `w.children.Done()` and `w.working.Unlock()`, so
  the next `Process` call deadlocks. Both the defer and the caller get fixed.
- **#23 — understated.** `ldbManager.Add` with a stale-but-known previous
  does not "silently return nil" — it **corrupts the store** (frontier
  pointer overwritten, stale patch applied on top of frontier state,
  height-keyed patch/rollback records clobbered). Root cause: the guard at
  versioned_db.go:361-363 compares `previous` against the frontier of the
  *historical view at previous*, which is a tautology. Verified empirically.
- **#24 — broader than catalogued.** Not latent: through any `ldbManager.Get`
  historical view, every key created *after* that version reads as
  `([]byte{}, nil)` / `Has == true` on point-reads while iteration correctly
  omits it. Three inconsistent length conventions (enable_delete: 0 = deleted;
  patch.go ApplyWithoutOverride tombstone: `[]byte{0}` = length 1;
  skip_deleted iterator: length <= 1 = deleted). Quarantined (see below).
- **#41 — parenthetical wrong.** `GetLegacyPillarList` already guards
  `len(iterator.Value()) == 0` (since the initial commit); only
  `GetSwapAssets` lacks the guard.
- **#57 — location correction.** The "is nor provided" string lives in
  `verifier/errors.go:59`, not `verifier/account_block.go`.
- **#60 — behavior refinement.** The inverted guard means the binary-search
  fallback never runs *in the fork case it exists for*, and always runs
  (wastefully, ~log2(height) extra round-trips) in the common match case —
  which is why sync still works today and the bug went unnoticed.
- **#62 — refinement.** The nil panic is the `nodeManager.node` field read
  inside `Manager.Stop` (app/manager.go:88), not the method call itself.
- **#7 — extra impact.** `GetAllActive` appends the nil `toSentinelInfo`
  result, producing `null` entries in the JSON page.
- **#47 — extra scope.** Same `common.Big0` aliasing also at
  vm/embedded/implementation/pillars.go:423, 452, 468.

## Quarantine: consensus-sensitive — do NOT fix without spork gating / upstream coordination

Fixing any of these changes which sends/blocks are accepted or how embedded
contract state evolves; un-sporked changes would fork the node from the
network (or break replay from genesis). Each has full evidence + a repro
test sketch in the verification record; raise upstream.

- **#39** — user-block `ChangesHash` is never validated; enforcement must be
  height/spork-gated (precedent: `ReceiverMismatchEnforcementHeight`).
  Garbage values may already exist on-chain; unconditional enforcement could
  break resync.
- **#43** — liquidity `updateLiquidityRewards`: with ≥ 11 due epochs, the
  MaxEpochsPerUpdate cap (20 *blocks* = 10 epochs) is checked after
  `checkAndPerformUpdateEpoch` persists the epoch marker → capped epoch's two
  mint blocks are never emitted. Pre-bridge-spork path only (getOrigin /
  getAccelerator registrations); changing it risks altering historical replay.
- **#44** — duplicate guardian addresses: nomination accepts duplicates; vote
  loop breaks at first matching slot; threshold counts slots → 6 slots / 3
  unique guardians = deadlocked administrator recovery. Fix (reject
  duplicates in ValidateSendBlock) changes send acceptance → spork.
- **#45** — accelerator `AddPhase`/`UpdatePhase` validate neither Amount nor
  TokenStandard; tokens sent with a *successful* call are silently absorbed
  (failed receives are refunded). Zero-amount rule in ValidateSendBlock
  changes send acceptance → spork.
- **#49** — liquidity `SetAdditionalReward` lacks `CheckSecurityInitialized`
  (all siblings gate on it); with security uninitialized its time challenge
  runs with default MinSoftDelay. Still administrator-gated + time-challenged
  (defense-in-depth gap, not an auth bypass). Adding the check changes
  execution → spork.
- **#50 (state machine)** — a project whose votes pass only after the 14-day
  window, with no in-window Update, is Closed without a final tally. Fixing
  the tally-at-expiry alters project status evolution → spork. (The
  misleading "passed voting period" log is fixed in this batch.)
- **#24** — common/db tombstone/empty-value conflation: historical views feed
  election reads (consensus/election.go:135,149); most store getters treat
  ErrNotFound and zero-value-from-empty-bytes equivalently, which must be
  proven per call site before unifying the conventions.
- **#32 (two sub-items)** — the mailbox `unreceivedBlockPrefix` write is
  dead-as-an-index but **live in every momentum's validated ChangesHash**;
  removing it would hard-fork. The `AccountBlockHeaderComparer` `<=` → `<`
  change is order-identical for unique keys but orders momentum content —
  left alone.
- **#42 (item 1)** — `GetAllPillarVotes` per-id prefix scan optimization is
  result-identical but runs inside contract execution — upstream with tests.
- **#48 (item a)** — `computeDetailedPillarReward` ignoring the
  `GetPillarsList` error: propagating it flips a silent success into a failed
  receive in one (practically unreachable, DB-fault-only) corner —
  conservative call: bundle upstream/spork.
- **#53 (JSON tag)** — `exceptedBlockNum` tag is never serialized by any
  registered RPC endpoint in-repo, but external marshallers of
  `consensus/api.EpochPillarStats` would break on a tag change. Batch fix
  renames the Go field only and keeps the tag.

## Notable severity call-outs (fixed in this batch)

- **#26 (catalogue's "highest severity" — holds).** Both swallowed Apply
  errors in `momentumStore.AddAccountBlockTransaction`
  (chain/momentum/ledger_store.go:52-54, 81-83). On the *production* path a
  pillar with a local DB fault would sign and broadcast a momentum built on
  corrupt local state (local self-fork); on the validation path the momentum
  is rejected with a misleading `ErrMChangesHashInvalid`. `return err` is a
  no-op on the success path.
- **#23.** Store corruption via `ldbManager.Add` (see corrections above).
- **#60.** One-character fix (`if hash.IsZero()` → `if !hash.IsZero()`),
  three independent proofs of inversion (branch semantics, godoc'd intent,
  go-ethereum original). Sync-critical: recommend a live sync verification
  on testnet/devnet before merging, in addition to unit coverage.
- **#34.** `GenerateAutoReceive` verifies a possibly-nil block before
  checking the generation error; no recover on that path → pillar process
  panic. Fix is a reorder.
